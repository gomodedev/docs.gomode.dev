# Go Mode documentation website

This repository owns docs.gomode.dev, built with VitePress and hosted as Cloudflare Workers static assets. Documentation covers the reusable Go Mode platform. caic owns coding-agent workflows; its UI and md documentation belong at docs.caic.xyz.

## Source of truth

Read `/home/user/src/gomode/README.md` and the relevant source before updating pages; gomode documents contracts in comments beside the owning source and keeps no user guides. This site owns user and integration guides. Design plans are not shipped behavior. Native external-browser login and progressive skill activation must not be described as implemented until source proves them.

Read current [Cloudflare documentation](https://developers.cloudflare.com/workers/static-assets/) before changing deployment configuration. Configure navigation in `.vitepress/config.ts` and presentation in `.vitepress/theme/`. Keep the theme palette equal to the Brand table in gomode.dev’s README.

## Authoring and validation

Each guide page starts with one H1. Use H2 and H3 sections, language-tagged code blocks, and relative internal links without `.md`. Frontmatter belongs on the homepage. Check code examples against the actual upstream API.

Install hooks with `scripts/install-git-hooks.sh` before changes. Run `pnpm run fix`, `pnpm run verify`, `pnpm run build`, and `pnpm exec wrangler deploy --dry-run`. Verify desktop/mobile navigation, local search, keyboard interaction, screenshots, and 404 responses in a browser.

## VitePress patch

`patches/vitepress@1.6.4.patch`, applied through `patchedDependencies` in `pnpm-workspace.yaml`, makes local search return focus to the Search button when Escape closes it. Without it, focus falls to the page body and keyboard users lose their place. `tests/site.spec.ts` checks it. VitePress 1.6.4 and 2.0.0-alpha.21 still lack the fix. When VitePress changes version, keep the patch only if the new `VPLocalSearchBox.vue` still omits `setReturnFocus`, and regenerate it with `pnpm patch vitepress`.

## Captures

Go Mode produces native WebP captures in `e2e/screenshots/android`. Real host frontend captures come from caic’s `e2e/screenshots/frontend` and mddb’s `e2e/screenshots/docs`; these use sample data from their screenshot suites. Publish the referenced captures with `uv run --locked python scripts/publish_screenshots.py` from this website checkout. `public/favicon.svg` is generated from the Android launcher icon; publish it with `uv run --locked python scripts/publish_favicon.py ../docs.gomode.dev` from the gomode checkout and never edit it by hand. Identify browser frontend captures separately from native Android captures. Do not imply that Halo settings prove a physical device connection.

Builds use committed captures without a sibling checkout or emulator. Do not hand-edit generated images. External Workers Builds and custom-domain setup is documented in README.md.
